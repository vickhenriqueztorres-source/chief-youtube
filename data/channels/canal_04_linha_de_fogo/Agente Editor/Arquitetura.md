Montei a arquitetura completa do projeto, pronta para colar e passar para o Antigravity, Claude Code ou Codex executar. Não tem código, só estrutura, contratos de dados e ordem de construção. Uma decisão já vem embutida: o sistema é um **estúdio para vários canais**. O Linha de Fogo entra como o primeiro "pacote de marca" (Brand Pack). O Outro Lado, o Brecha e os próximos canais reaproveitam o mesmo pipeline trocando só esse pacote. ````markdown # DOC STUDIO — Arquitetura Completa do Projeto **Pipeline automatizado de documentários para YouTube · Canal piloto: Linha de Fogo** Versão 1.0 · Executores: Antigravity / Claude Code / Codex · Orquestração: LangGraph --- ## 1. Visão geral ### 1.1 O que o sistema faz Recebe um **tema** e entrega um **episódio pronto para publicar**: vídeo 4K de 11–14 min, 3 thumbnails, 2 Shorts, título, descrição e relatório de QA. ### 1.2 Princípios de arquitetura 1. **A IA gera PEÇAS, o código monta a CENA.** Nenhuma imagem gerada vira frame final sem passar por recorte, tratamento e composição. 2. **Arquivos em disco são a fonte da verdade.** O estado do LangGraph guarda só caminhos e IDs, nunca imagens ou áudio em memória. 3. **Todo nó é idempotente.** Rodar de novo o mesmo passo com a mesma entrada gera o mesmo resultado (ou usa o cache). 4. **Contratos de dados rígidos.** Cada etapa lê e escreve arquivos validados por um schema compartilhado entre Python e TypeScript. 5. **A voz manda no tempo.** A timeline é ancorada nos timestamps das palavras da narração, não o contrário. 6. **Marca é configuração, não código.** Paleta, fontes, prompts, movimentos e regras de QA ficam num Brand Pack por canal. 7. **Humano só onde importa.** 3 aprovações obrigatórias: roteiro, animatic e vídeo final. ### 1.3 Diagrama de camadas ``` ┌──────────────────────────────────────────────────────────┐ │ CAMADA DE REVISÃO Relatórios HTML / Painel (fase 2) │ ├──────────────────────────────────────────────────────────┤ │ CAMADA DE ORQUESTRAÇÃO LangGraph (Python) │ │ grafo principal + subgrafos + checkpoints + interrupts │ ├──────────────────────────────────────────────────────────┤ │ CAMADA DE SERVIÇOS │ │ imagegen · cutout · look · tts · audio · qa · library │ ├──────────────────────────────────────────────────────────┤ │ CAMADA DE RENDER Remotion (TS) + FFmpeg │ ├──────────────────────────────────────────────────────────┤ │ CAMADA DE DADOS │ │ schemas · brand packs · biblioteca · episódios · cache │ └──────────────────────────────────────────────────────────┘ ``` --- ## 2. Serviços (camada de ferramentas) Cada serviço tem **uma responsabilidade**, roda sozinho por linha de comando (para testes) e é chamado pelos nós do grafo como tool. ### 6.1 `imagegen` - **Interface única:** recebe `ElementSpec` + Brand Pack e devolve 1–N arquivos brutos. - **Adaptadores:** `codex_cli` e `gemini_cli`, escolhidos por configuração e com fallback de um para o outro. - Monta o prompt a partir de: prompt-base do Brand Pack + módulo do tipo de elemento + `subject` + regra de isolamento ("fundo liso off-white, elemento único, sem texto"). - **Fila com limite de concorrência** e backoff (a CLI tem limites de uso). - **Cache por hash** do prompt + referência: o mesmo pedido não gera de novo. ### 6.2 `cutout` - rembg como padrão. - **Métricas de borda:** área do alfa, fragmentos soltos, halo claro, % de bordas cortadas. - Reprovou? Tenta SAM2 com ponto central. Reprovou de novo? Devolve para `imagegen` com o prompt ajustado. ### 6.3 `look` - Aplica **a receita única** do `look.yaml`: cinza → curva → posterize → mapeamento de paleta → halftone → borda rasgada. - Gera a peça **neutra** (preto + papel). O duotone do ato é aplicado depois, no render. - Salva a versão tratada + uma miniatura para revisão. ### 6.4 `tts` - Gera a narração por ato (fica mais fácil refazer só um trecho). - Guarda os **timestamps de cada palavra** e aplica as pausas de 1 s antes de valores e traições. - Normaliza a voz antes de entregar ao `audio`. ### 6.5 `audio` - Monta a trilha por ato, posiciona os SFX, aplica ducking sob a voz, silêncios e mix final. - Mede loudness (−14 LUFS / −1 dBTP) e corrige automaticamente. ### 6.6 `library` - Índice SQLite com tags, época, país e tipo. - **Busca em duas etapas:** filtro por tags e, na fase 2, similaridade visual/textual por embeddings. - Deduplicação por hash perceptual. - Registra **uso por episódio** (para evitar a mesma peça em destaque em episódios seguidos). ### 6.7 `qa` | Checagem | Onde | Método | |---|---|---| | Texto dentro da peça | Asset | OCR | | Rosto fotorrealista | Asset e frame | Detector de rosto + análise de textura | | Qualidade do recorte | Asset | Métricas do `cutout` | | Paleta e proporção | Frame | Histograma quantizado na paleta oficial | | Tempo por plano | Timeline | Leitura do `SceneSpec` | | Legibilidade da thumb | Thumbnail | Redução para 160 px + OCR | | Loudness | Áudio | FFmpeg | | Aderência ao estilo | Frames amostrados | LLM de visão comparando com `reference/` | | Coerência histórica | Roteiro e shots | LLM com as fontes do roteiro | --- ## 7. Orquestração (LangGraph) ### 7.1 Estado do grafo (`EpisodeState`) | Campo | Conteúdo | |---|---| | `episode_id` / `channel` | Identificação | | `stage` | Etapa atual | | `artifacts` | Caminhos dos arquivos (script, narration, shotlist, scenes, audio, renders) | | `pending_elements` | Peças que ainda precisam ser geradas | | `assets_map` | `element_id → asset_id` | | `qa_findings` | Problemas abertos e a quem foram devolvidos | | `retries` | Contador por nó/elemento | | `approvals` | Situação das 3 aprovações | | `cost` / `timings` | Métricas da execução | ### 7.2 Grafo principal ``` START │ ▼ [research] Pesquisador: reúne fatos, datas, valores e fontes │ ▼ [script] Roteirista: 6 atos, beats, open loops, texto de tela │ ▼ [fact_check] Checador: confronta o roteiro com as fontes │ ▼ ✋ INTERRUPT: aprovação do roteiro │ ▼ [narration] Voz (ElevenLabs) + timestamps │ ▼ [shotlist] Decupador: beats → takes → elementos + camadas de código │ ▼ [assets] ── SUBGRAFO DE PEÇAS (paralelo por elemento) ──┐ │ │ ▼ │ [compose] Compositor: gera 1 SceneSpec por take │ │ │ ▼ │ [audio_plan] Sonoplasta: trilha + SFX + silêncios │ │ │ ▼ │ [animatic] Render rápido (540p, sem textura) │ │ │ ▼ │ ✋ INTERRUPT: aprovação do ritmo │ │ │ ▼ │ [render] ── SUBGRAFO DE RENDER (paralelo por ato) ──┐ │ │ │ │ ▼ │ │ [mix] Áudio final + mux com o vídeo │ │ │ │ │ ▼ │ │ [qa] QA automático ──── reprovado ──► roteia para o nó responsável │ aprovado ▼ [packaging] 3 thumbnails + 2 Shorts + título/descrição/capítulos │ ▼ ✋ INTERRUPT: aprovação final │ ▼ END (status = final_ok) ``` ### 7.3 Subgrafo de peças (1 execução por elemento, em paralelo) ``` [library_lookup] ── encontrou ──► [link_asset] ──► fim │ não encontrou ▼ [generate] ──► [cutout] ──► [cutout_qa] │ reprovado (≤ 2x) ──► [generate] com prompt ajustado │ reprovado (3ª vez) ──► marca para revisão humana ▼ aprovado [look] ──► [asset_qa] ──► [register_asset] ──► fim ``` ### 7.4 Subgrafo de render - Renderiza **por ato** (ou por blocos de ~60 s) em paralelo. - Cada bloco é cacheado pelo hash do seu `SceneSpec` + assets: mudou uma cena, só aquele bloco é refeito. - O FFmpeg concatena os blocos e faz o mux com o áudio final. ### 7.5 Roteamento de correções (a partir do QA) | Problema | Volta para | |---|---| | Peça com texto, rosto realista ou recorte ruim | Subgrafo de peças (só aquele elemento) | | Paleta/proporção fora do padrão | `compose` (aquela cena) | | Plano parado demais | `compose` (divide ou adiciona movimento) | | Loudness fora | `mix` | | Erro factual | `script` → exige nova aprovação humana | | Thumb ilegível | `packaging` | **Regra:** a correção é sempre **cirúrgica** (cena ou elemento), nunca "refazer o episódio". ### 7.6 Aprovações humanas (interrupts) - O grafo pausa e grava o checkpoint. - O sistema gera um **relatório de revisão** (HTML local): roteiro com fontes, contact sheet dos takes, animatic com player, lista do QA. - O humano responde com `aprovar`, `reprovar com nota` ou `editar arquivo`, e o grafo retoma do mesmo ponto. - Toda aprovação fica registrada no `Episode.approvals` com a versão do artefato. ### 7.7 Modelos por nó (configurável em `config/`) | Nó | Perfil de modelo | |---|---| | research, script, fact_check | Modelo forte de raciocínio e escrita | | shotlist, compose | Modelo forte com saída estruturada (JSON validado) | | audio_plan, packaging | Modelo médio | | qa (visão) | Modelo multimodal | Toda saída estruturada é **validada contra o schema**. Se inválida, o nó tenta de novo com o erro de validação no prompt (máx. 2 vezes). --- ## 8. Renderer (Remotion) ### 8.1 Composições | Composição | Uso | |---|---| | `Episode` | Vídeo completo (lê a lista de SceneSpecs) | | `ActBlock` | Um ato ou bloco, para render paralelo | | `Scene` | Uma cena isolada (preview e testes) | | `Thumbnail` | Frame estático 1280×720 | | `Short` | 1080×1920 a partir de cenas do longo | | `StyleTest` | Frame de teste comparado com o painel de identidade | ### 8.2 Componentes visuais | Componente | Função | |---|---| | `PaperBackground` | Papel com textura e variação sutil | | `AssetLayer` | Peça recortada com duotone e blend | | `HalftoneMap` | Mapa-múndi e rotas | | `DiagonalSlash` | O corte-assinatura (faixa, rastro, rasgo) | | `TextBlock` | Palavra em bloco de papel recortado | | `Stamp` | Carimbo de valores e revelações | | `ChapterCard` | Cartela de capítulo (número romano em mostarda) | | `LowerThird` | Nome e cargo | | `Counter` | Contador de dinheiro do Ato 4 | | `GrainOverlay` | Grão global | | `Misregistration` | Desregistro de cor | | `Watermark` | Logo compacto | ### 8.3 Regras do renderer - **Tudo vem do Brand Pack**: nenhuma cor, fonte ou tempo fixo no código. - Movimentos só do vocabulário oficial; um movimento desconhecido no JSON gera erro. - Animação de papel a 12 fps efetivos; câmera a 24 fps. - **Modo proxy** (animatic): 540p, sem grão/halftone, render rápido. - **Modo final**: 4K com toda a pilha de textura. --- ## 9. Segurança, direitos e compliance (YPP) - Nenhuma foto de terceiros no pipeline.
